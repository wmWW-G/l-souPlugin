# 来搜工作台：安装与首次测试

适用：Windows 10/11（Intel/AMD 64 位）、Intel Mac、M 系列 Mac。1.0.2 的来搜窗口和随包 Node 构建目标为 macOS 11.0，但依赖的 WorkCTL 0.1.55 已在 macOS 11.5.2 报告系统符号缺失；当前整套插件不能宣称兼容 macOS 11，Mac 请使用 macOS 12.0 或以上并实机验证。仅提供三个独立安装包：Mac（M芯片）、Intel Mac、Windows（x64），请按电脑选择对应ZIP。

## 只需三步

1. 打开并登录 Accio Work，在「插件 → 添加插件 → 导入插件」中选择整个 ZIP，无需手工解压。
2. 安装启用后，在 Accio 对话中说「打开来搜插件」，显示来搜启动页。
3. 点击橙色「启动工作台」，打开桌面窗口；查看「数据看板」和「数据分析与优化」中的当前店铺数据。

不要安装 Node/Rust，不需要命令行，也不用访问浏览器网址。需提前在当前空间安装「国际站生意助手」并授权自己的店铺。当前分析按钮使用 Accio Work 的分析能力；旧版运营待办的独立配置入口保留，未配置不影响店铺数据连接。

## 交给 Accio Work 的安装 Prompt

请安装并启用我提供的「来搜工作台」插件 ZIP。通过插件管理界面导入，不要重新编译源码或要求我敲命令。安装后在对话里展示来搜 HTML 启动页，等我点击「启动工作台」再打开 Tauri 桌面窗口和数据看板，使用我当前活动空间的国际站生意助手授权读取真实数据，再检查数据分析与优化页。不要发布商品或修改广告。若无法使用，请读取本机来搜工作台日志，判断是插件启动、缺少店铺授权还是平台环境问题，用一句话告诉我应该点哪里；不要让我排查技术细节，不要输出账号令牌或 API Key。

## 遇到问题

1.0.3 内置「来搜启动排障」Skill。直接在 Accio Work 中说：**“用来搜启动排障 Skill 检查并恢复工作台。”** 它会检查当前会话、实际安装的工具、系统与包内程序，自动重新定位更新后的工具，并尝试恢复来搜自身的执行权限或失败窗口。登录、插件安装或系统兼容问题会给出对应原因和需要点击的入口。

恢复完成后仍需确认 Tauri 窗口已打开，并能在经营总览、商品运营看到当前店铺数据。排障不会发布商品、修改广告、复制账号凭据或关闭系统保护。如果系统提示未知发布者或拦截，把实际提示反馈给提供插件的人。

供 Accio 排查：macOS 日志在 ~/Library/Application Support/com.lsou.workbench/；Windows 日志在 %LOCALAPPDATA%/com.lsou.workbench/。只回传不含敏感信息的错误摘要。Windows 依赖 Microsoft WebView2；若缺少，使用 Microsoft 官方安装入口解决，不要求用户安装开发工具。

MCP 提供启动页、状态、打开、诊断、有限恢复、停止工作台，以及更新准备、取消更新和退出插件连接九个入口。桌面/MCP 不可用时，Accio 可执行 `lsou-workbench --diagnose` 获取相同的脱敏检查；完整步骤见包内 `skills/lsou-startup-recovery/SKILL.md`。诊断不输出原始日志或账号文件。最后一次启动摘要保存在本机 `startup-status.json`，须结合时间和进程状态判断，不能当作当前成功证据。

## 1.0.4 启动页

新版插件连接后先待命。启动页由内置 `lsou-launchpad` Skill 在 Accio 对话内渲染，按钮向当前对话发送启动、状态或排障请求，随后调用对应工具。卡片不会用动画假报成功；后端结果与桌面数据分别核验。独立打开 HTML 仅供设计预览。安装详情页自动弹出 HTML 尚无已确认的入口，不能与对话里的启动页混为一谈。

## 1.0.5 Windows 诊断复测

本轮Windows包修正慢启动时的工具响应：20秒内仍未完成则返回“仍在启动/恢复”，由Accio稍后读取状态；这不代表启动成功，也不需要重复开窗口。新增本机 `native.log` 和诊断里的 `nativeStartup.events`，用于确认卡在原生程序、Node创建、Windows进程管理还是后端退出。日志只保存阶段和数值错误码。`lastStartup.source=standalone` 表示一次独立后端运行，不能证明工作台窗口成功。若仍卡住，让Accio读取诊断并反馈原生阶段摘要。此包仍需Windows实际导入、点击启动和店铺数据验收。

## 1.0.8 启停增强版（lifecycle-r1）

可以直接说“启动来搜工作台，跳过 HTML 动画”；关闭时说“停止来搜工作台”。停止只处理当前 MCP 启动的窗口并触发所属后端清理，插件保持待命，再说启动即可。重复停止会合并，停止请求会取消在途恢复；无需卸载插件。状态中的 buildRevision 为 lifecycle-r1。

本次增强仅更新启动脚本与 Skill，沿用 1.0.8 原生程序和业务资源；不包含自动更新功能。后端 ready、窗口可见、真实数据加载是三个独立验收层次，工具未观察窗口或数据时不会标成已验证。Windows 仍需实测启停与重新启动。

## 1.0.9 图片上传

产品发布页的新图片通过 Accio Work 自带 CDN 上传，无需配置存储桶。图片上传成功后自动带入发品资料；发布仍使用原有确认及串行队列。图片接口已在 Accio Work 0.32.2 核验；登录失效、版本不支持或上传失败会在图片旁提示并保留重试入口。

## 1.0.10 完整工作台

包含当前界面、31项报告分析和1项任务生成，以及录入保存、所选日/周/月、报告回传与本地历史。分析采用点击时选定的范围，各来源自己的统计周期分别保留；分析和任务数据按账号隔离存储在本机，更新插件不需要删除这些数据。

Windows 保留已修复的启动路径处理、随包 Node、原生错误日志和停止后重新启动能力。旧版先关闭来搜窗口再更新；具体操作以本文末尾的更新步骤为准。不要手动清空本地配置和历史目录。

本版为标准包，不包含开发店铺快照、示例商品或内部测试密钥。三个平台分别打包；Windows 与 Intel Mac 的构建检查不等于目标电脑的实机验收。当前版本没有自动更新功能。

## 1.0.11 Windows 分析对话唤起修复

Windows 的“开始分析”和“生成任务”改用系统注册协议方式打开 Accio Work，修复部分电脑通过资源管理器中转时没有新对话的问题。完整链接独立传递，保留中文和特殊字符；失败时日志只记录系统错误码及脱敏诊断，界面不再将所有故障解释为未登录。

早期修复包构建标识为20260918-win-protocol-r1；以下更新辅助修订版同时保留该协议修复。本次交付Windows 1.0.11，Mac继续使用已交付的1.0.10。新包仍需Windows确认实际新对话投递；不要求进行分析效果评审，不会自动重发旧失败请求或清除历史。

## 1.0.11 更新辅助修订版：停止与直接更新

安装此修订版后，可以直接在 Accio 中说：

- **“停止来搜工作台”**：关闭当前连接打开的窗口，插件待命，之后可以再启动。
- **“停止整个来搜插件”**：关闭所属工作台，再退出当前插件连接。
- **“停止来搜并准备更新”**：执行上述停止，并给出保留数据的更新步骤。
- **“准备更新，暂不退出连接”**：停止并阻止再次启动；说“取消来搜更新”可以恢复待命。

启动页也有“停止插件”和“准备更新”两个按钮。停止只管理当前插件连接及其窗口，不按进程名称关闭其他程序；宿主若自动重新连接，不能视为已全局停用。更新前请保存还没提交的填写内容。

**通常不必先卸载：**在 Accio 的「插件 → 添加插件 → 导入插件」再次选择同平台新版 ZIP，完成安装流程，再打开来搜。保持插件 ID 不变；本修订版文件名含 `update-r2`，实际版本为1.0.11，构建标识为20260918-update-r2。

如果 Windows 提示文件被占用，完全退出 Accio Work（包括系统托盘）后重新打开，先导入再启动来搜。旧版还没有上述停止入口时，先关闭来搜窗口并完全退出 Accio，重新打开后导入本包即可。

上述覆盖导入依据为 Accio Work 0.32.6 的本机源码：标准 ZIP 导入按插件 ID 使用固定暂存来源，同一来源允许再次安装；未在 Windows 实机执行本次更新。不同安装来源或宿主版本若提示来源冲突，按宿主界面处理旧来源，不手工覆盖安装文件或修改注册表。当前没有自动下载新版包功能，普通“检查更新”不能替本地 ZIP 找到新包。

更新和上述停止操作不删除已保存的本机配置、录入和分析历史。只核对实际版本即可，不需要重新跑分析来检验效果。
